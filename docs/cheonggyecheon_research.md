## 2. 도로 형상 (OpenStreetMap)

- 데이터: `data/osm/cheonggyecheon.osm` (© OpenStreetMap contributors, ODbL), Overpass API, 2026-11-03 수집, 1.6MB
- 범위: 경도 126.9755~127.0050, 위도 37.5655~37.5735
- 청계천로는 OSM에서 **청계천 양쪽의 일방통행 2개(각 2차로)** 로 표현됨. `highway=secondary, oneway=yes, lanes=2`
- 셔틀 동행 경로 길이: **2,146m** (직선 거리로 계산한 청계광장~광장시장 약 2.1km와 일치)

## 3. 가정 (근거가 부족해서 채운 값)

| 항목 | 값 | 이유 |
|---|---|---|
| 청계천로 제한속도 | 30km/h | OSM이 일부 구간에 `maxspeed=30`으로 태그. 나머지 구간에 같은 값 적용 |
| 그 외 도로 속도 | 50/40/30/20km/h (도로 등급별) | OSM에 값이 없어 도시부 일반값 사용 |
| 신호 현시 | netconvert 기본 | 청계천로 현시 자료를 못 구함 (서울 T-DATA 신호 API는 인증키 필요) |
| 교통량 | 본선 500대/h(방향별), 측면 합류 40대/h×8곳, 오토바이 120대/h | 실측 자료 없음. 조정 가능 |
| 셔틀 제원 | 길이 5m, 가속 1.5, 감속 4.0 | ROii 제원을 확인 못 함 |
| 정류소 정차 | 아직 미구현 | 정류소 좌표를 OSM 추출에 포함하지 않음 |
| 횡단보도·보행자 | 아직 미구현 | 다음 단계 |

## 4. 끼어들기 요인을 시뮬레이션에 넣은 방법

1. 측면 도로 합류: 본선으로 들어오는 8개 측면 도로에서 `cutin_car`(차선변경·합류에 적극적) 투입
2. 불법주정차: 본선 우측 차로에 25~50초 정차하는 차 4곳 → 뒤차가 옆 차로로 끼어듦
3. 오토바이: 폭 0.8m, 가속이 좋고 간격이 좁은 별도 차종
4. 일반 차량 controller 4종 혼합 (Krauss 35 / IDM 30 / EIDM 20 / ACC 15%, 수업 기본과 동일)

## 5. 검증 결과 (헤드리스, 1,800초 × 난수 5회)

- 셔틀 소요 420~470초, 대기 5~50초
- 순간이동(teleport) 5회 합계 3건 / 약 4,000대
- 합류부에서 계속 막히던 측면 도로 3곳은 제외 (`tools/make_cgc_scenario.py`의 `BAD_SIDE`)
